## 1. 目标与范围

### 1.1 核心场景

在资源管理器中整理文件时，把常用文件夹"拖出"到屏幕边缘的临时停靠层，形成可随时拖回的悬浮快捷入口。
资源管理器切到前台时停靠层出现，切走时完全消失，不占用任何常态视觉空间。

### 1.2 功能边界

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 从资源管理器拖出文件夹生成悬浮图标 | P0 | 主入口 |
| F2 | 热键 `Ctrl+Shift+D` 从当前选中项生成图标 | P0 | 拖拽失灵时的兜底通道 |
| F3 | 停靠层仅在资源管理器前台时显示 | P0 | 切走即隐藏 |
| F4 | 图标拖回资源管理器 = **标准 OLE drop** | P0 | 同盘移动 / 跨盘复制，交给系统处置（见 3.4） |
| F5 | 拖到同侧末端角落的删除区 = 移除图标 | P0 | 仅移除条目，绝不触碰硬盘数据 |
| F6 | 双击图标 = 在资源管理器中打开该文件夹 | P1 | |
| F7 | 图标拖到其他第三方应用 = 提供标准 `CF_HDROP` | P1 | 复用系统拖放，零额外成本 |
| F8 | 开机自启 / 图标排序 / 使用频率统计 | P2 | 后置 |
| F9 | **图标老化衰减，到期自动消失** | P1 | 新增，见 3.6 |
| F10 | **路径自动跟随：源文件夹被移动/重命名后，图标链接同步更新** | P1 | 新增，见 3.4.1 |

## 2. 总体架构

```
DropBridge
├── Native/           Win32 P/Invoke 与 Vanara 封装
├── ShellWatcher      前台窗口监视（事件驱动）
├── DragDetector      拖拽起始检测（隐形唤出的关键）
├── DropTargetHost    IDropTarget 实现，挂在停靠层窗口上
├── DockWindow        停靠层主窗口（Dock / Drop 两种模式）
├── IconProvider      图标提取 + 磁盘缓存
├── ItemStore         数据模型 + JSON 持久化
├── AgingService      老化衰减计算（纯函数 + 定时刷新）
├── ShellNotifyWatcher  Shell 变更通知监听（F10 路径自动跟随）
├── HotkeyService     RegisterHotKey 封装
└── TrayIcon          托盘图标与设置入口
```

`CopyService`（原 `IFileOperation` 封装）**已移除**。

### 2.1 窗口模型

只有一个主窗口，三种状态：

| 状态 | 触发条件 | 形态 |
|---|---|---|
| **隐藏** | 无图标 + 无拖拽，或资源管理器不在前台 | 窗口 `Hide`，零存在感 |
| **Dock** | 有图标 + 资源管理器在前台 | 屏幕**左侧或顶部**边缘的一条停靠带（默认左侧，宽 96px） |
| **Drop** | 检测到从资源管理器发起的拖拽 | 停靠带**原地**展开接收区（虚线高亮），松手后 800ms 淡出回 Dock |

### 2.2 停靠位置与分区

**确定停靠在屏幕左侧**，固定贴边，不跟随鼠标。停靠带垂直占屏幕 15%~85%，自上而下分三个区段：

| 区段 | 位置 | 行为 |
|---|---|---|
| **固定区（Pin）** | 顶部 | 拖入即永久保留，**从不老化**，且不受拥挤加速影响 |
| **临时区** | 中部 | 正常老化；条目越多老化越快（见 3.6） |
| **删除区** | 底部末端（左下角） | 拖入即移除条目；也是老化位移的终点 |

固定区与临时区之间有一条分隔线。固定区最大高度不超过屏幕高度的 40%，
超出后固定区内部滚动，避免挤压临时区。

删除区常显为一枚低透明度的回收图标（约 40×40），拖拽进入时放大高亮。
放在最末端是为了让老化位移方向与之一致，形成"顺流而下"的视觉连贯感。

### 2.3 窗口样式

`WS_EX_TOPMOST | WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`

- `TOPMOST` 压在资源管理器之上
- `LAYERED` 逐像素 alpha（半透明与圆角）
- `TOOLWINDOW` 不进 Alt-Tab 与任务栏
- `NOACTIVATE` 点击不抢焦点（否则前台判定会抖动）

## 3. 关键流程

### 3.1 前台检测

```
SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)
  → GetForegroundWindow()
  → GetClassName() ∈ { CabinetWClass, ExploreWClass }
  → GetWindowThreadProcessId() → 进程名 == explorer.exe
  → 双重命中才判定为「资源管理器前台」
```

补充监听 `EVENT_OBJECT_DESTROY`，防止窗口关闭后状态残留。

### 3.2 拖出接收（F1）

1. `DragDetector` 判定拖拽开始（见 3.3）
2. 停靠层切 Drop 模式并显示，`RegisterDragDrop`
3. 用户把文件夹拖到接收区 → `IDropTarget.DragEnter` 高亮 → `Drop`
4. 从 `IDataObject` 取 `CF_HDROP`，`DragQueryFile` 枚举路径
5. 过滤：只接受目录，去重，排除已在列表中的路径
6. 生成条目，异步提取图标，写入存储
7. 面板收起，回到 Dock 模式

### 3.3 隐形唤出（拖拽起始检测）

```
WH_MOUSE_LL 捕获 WM_LBUTTONDOWN
  → 起点落在资源管理器窗口客户区内（排除标题栏/地址栏）
  → 记录起点坐标，进入「待定」状态
WM_MOUSEMOVE 且 VK_LBUTTON 仍按下
  → 位移 > GetSystemMetrics(SM_CXDRAG)（默认 4px）
  → 判定为拖拽开始，唤出 Drop 接收区
```

**降级方案（Plan B）**：若实测 explorer 进入 OLE 拖放循环后钩子收不到 `WM_MOUSEMOVE`，
改用 30ms 定时器轮询 `GetCursorPos` + `GetAsyncKeyState(VK_LBUTTON)`，逻辑完全相同。
预留一行开关切换。

**必须排除的误触发**：`WM_LBUTTONDOWN` 时若 `WindowFromPoint` 命中我们自己的窗口
（即从停靠层往外拖的 F4 动作），不唤出接收区。

### 3.4 拖回（F4）— 标准 OLE drop

改为标准 OLE 拖放后，这一段从原来的三段式（命中测试 + 取路径 + `IFileOperation`）**简化为十几行**：

```
DataObject data = new DataObject(DataFormats.FileDrop, new[] { item.Path });
DragDrop.DoDragDrop(iconElement, data, DragDropEffects.Copy | DragDropEffects.Move);
```

WPF 的 `DataObject` 会自动把 `DataFormats.FileDrop` 转成 `CF_HDROP`，
资源管理器、桌面、以及任何支持文件拖放的第三方应用都能直接接收。

**行为语义（由系统决定，我们不干预）**

| 场景 | 系统行为 |
|---|---|
| 同盘（如 `D:\A` → `D:\B`） | 移动 |
| 跨盘（如 `D:\A` → `E:\B`） | 复制 |
| 用户按住 `Ctrl` 拖 | 强制复制 |
| 用户按住 `Shift` 拖 | 强制移动 |
| 用户按住 `Alt` 拖 | 创建快捷方式 |

修饰键由资源管理器原生解释，我们零成本获得"按需复制/移动"能力。
拖拽期间在光标旁显示一行小字提示：`按住 Ctrl 复制 · Shift 移动`。

**⚠ 副作用：同盘移动会让快捷方式失效 —— 已由 F10 解决**

同盘拖回是移动，源文件夹被搬走后，悬浮图标指向的路径就不存在了，条目变成死链。
解决方式不是"事后猜新路径"，而是**监听 Shell 变更通知，拿到新旧 PIDL 直接改链接**（见 3.4.1）。
图标会在移动完成的几十毫秒内自动跳到新位置，用户几乎无感。

**遮挡问题的新解法**

改走 OLE 后，遮挡不再是"命中测试误判"，而只是"松手无效"——
用户能看到资源管理器没有出现 drop 高亮，会自然挪开。因此主方案就是**停靠带只占边缘一条**，
把干扰面积压到最小。

可选加固（约 3 行，建议保留）：拖拽发起时给窗口加 `WS_EX_TRANSPARENT`，
松手后移除。这样鼠标穿透后资源管理器可直接接收 drop，即便在停靠带上松手也有效。

**递归风险**：把文件夹拖进它自己的子目录，跨盘复制可能递归。
资源管理器自身会拒绝同盘的此类移动；跨盘场景交由 P3 补一次路径预判
（拖拽开始时用 `IShellWindows` 读一次当前目录，若是源的子孙则显示禁止光标）。

### 3.4.1 路径自动跟随（F10）

**原理**：同盘移动在 Shell 层面就是一次 rename。资源管理器执行完移动后，
Shell 会向所有已注册的监听者广播 `SHCNE_RENAMEFOLDER`，并在消息里同时带上**旧 PIDL 和新 PIDL**。
我们只要比对旧路径是否为某个条目，是则改写为新路径即可，全程无需猜测或搜索。

**注册**

```
SHChangeNotifyRegister(
    hwnd,                                        // 隐藏消息窗口
    SHCNRF_InterruptLevel | SHCNRF_ShellLevel,   // 两个 flag 都要，才能收到 Shell 自身发起的变更
    SHCNE_RENAMEFOLDER | SHCNE_RENAMEITEM        // 同盘移动/重命名
      | SHCNE_DELETE | SHCNE_RMDIR,              // 目标被删除 → 标记失效
    WM_APP_SHELLNOTIFY,
    1,
    &entry                                       // entry.pidl = NULL + fRecursive = TRUE，即全盘订阅
)
```

**处理**

```
收到 WM_APP_SHELLNOTIFY
  → lParam = 事件 ID，wParam = PIDL 对（dwpItem1 旧，dwpItem2 新）
  → SHGetPathFromIDList 转成路径字符串
  → 旧路径与 item.Path 匹配（规范化 + 大小写不敏感）
  → 命中则改写 item.Path，刷新显示名与图标缓存
  → SHCNE_DELETE / RMDIR 命中则标记条目失效（灰显）
```

**要点**

- 需要一个隐藏窗口接收消息（WPF 用 `HwndSource` 包一层，或直接用 `NativeWindow`）
- 消息里的 PIDL 仅在消息处理期间有效，不要缓存，也不要手动释放
- 全盘订阅的事件量虽大，但我们只比对少量条目路径，开销可忽略
- 跨盘复制产生的是 `SHCNE_CREATE`，源不变，无需处理
- `SHGetPathFromIDList` 对虚拟文件夹会失败 → 直接忽略

**白捡的两个能力**（这才是这个方案最值钱的地方）

1. 用户在资源管理器里**手动**移动或重命名文件夹，悬浮图标也自动跟随 —— 不限于我们的拖回操作
2. 文件夹被删除 → 自动灰显失效，不用等下次启动才发现

**实现量**：约 100~150 行（含 P/Invoke 与消息窗口），无管理员权限要求。

**降级路径**：若实测通知不稳定，退回简化版 ——
`DoDragDrop` 返回 `Move` 且源不存在时，用 `IShellWindows` 读当前 explorer 目录拼出新路径并校验存在性，
约 40 行，能覆盖"拖到空白处"这一最常见场景（约 90%）；仍失败则标记失效。

### 3.5 拖到删除区（F5）

拖拽期间删除区放大高亮，拖入松手即移除条目。
**只删条目，不删硬盘上的真实文件**，提示文案必须明写这一点。
右键菜单提供"移除"作为等价操作。

### 3.6 老化衰减（F9）

**默认生命周期 48 小时**，窗口隐藏期间照常老化。

#### 采用纯时间戳方案（拥挤加速后置）

```
progress = (DateTime.Now - item.LastUsedAt).TotalSeconds / lifetimeSeconds   // 默认 48×3600
renderPos = layoutPos + progress × travelDistance
progress ≥ 1 → 淡出并移除条目
```

这个方案的好处是"零后台负担"：

- **不需要常驻定时器** —— 窗口隐藏时完全不 tick，下次显示时按时间戳补算
- **不需要持久化老化进度** —— `LastUsedAt` 本来就在存，重启后接着算
- **天然满足"隐藏期照常老化"** —— 按真实时间差计算，与窗口是否显示无关

#### 拥挤加速：已后置

倍率在代码中抽成独立函数预留接口，当前恒为 1：

```
double GetAgingMultiplier() => 1.0;   // 将来接拥挤加速只改这里
```

为什么现在不做：一旦老化速度随条目数变化，纯时间戳就不再成立，
必须引入 `AgedSeconds` 持久化字段 + 30 秒常驻 tick + 休眠跳变保护（约 +60 行）。
为一个锦上添花的功能让核心模块背上常驻定时器和额外状态，不划算。

**将来要加的正确姿势**：把计时方式整体换成累积式，
`AgedSeconds += elapsed × multiplier`，并处理休眠导致的时间跳变（差值超 5 分钟按 5 分钟算）。
倍率公式沿用：`clamp(1 + max(0, n − SoftCap) × Step, 1, MaxMultiplier)`，
默认 `SoftCap=5 / Step=0.3 / 封顶 6×`（≤5 个 48h，8 个约 25h，12 个约 15h，≥22 个封顶 8h）。

#### 其余细节

- **位移方向**：沿停靠带向下，终点是删除区
- **可移动距离**：`travelDistance = 临时区可用长度 − 图标尺寸`，`progress = 1` 时正好落进删除区
- **回血**：拖回使用一次 → `LastUsedAt` 重置，带 0.3s 缓动滑回原位
- **固定区豁免**：`pinned` 条目不参与老化计算，永不消失
- **生命周期可选**：2 小时 / 12 小时 / **48 小时（默认）** / 7 天 / 永不
- **布局**：`Canvas` 直接改 `Canvas.Top`，避开 WPF 面板重排

实现量约 60~80 行。若实测观感不佳可整体关掉，关闭后即为普通静态图标列表。

### 3.7 热键通道（F2）

```
  → IShellWindows 取活动窗口 → Document.SelectedItems()

```

## 4. 数据模型与持久化

存储位置：`%LOCALAPPDATA%\DropBridge\`

```
items.json
icons\{path-sha1}.png
settings.json
```

`items.json`：

```json
{
  "version": 2,
  "items": [
    {
      "id": "8f3a...",
      "path": "D:\\Projects\\A项目\\a分区\\目标文件夹",
      "displayName": "目标文件夹",
      "addedAt": "2026-09-07T10:30:00+08:00",
      "useCount": 12,
      "lastUsedAt": "2026-09-07T18:02:00+08:00",
      "pinned": false
    }
  ]
}
```

`settings.json`：老化生命周期（默认 48 小时）、图标尺寸、透明度、是否开机自启、排序规则。

图标获取：`IShellItemImageFactory::GetImage(256)`，优先真实缩略图，失败回退 `SHGetFileInfo`。
按路径 SHA1 缓存到磁盘。启动校验路径是否存在，失效条目灰色虚化，右键可批量清理。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **UIPI 拦截拖放** | 以管理员运行时 explorer 无法拖入，功能全废 | manifest 锁 `asInvoker`；启动检测 `IsProcessElevated` 并弹警告 |
| **同盘移动致快捷方式失效** | 源文件夹被搬走，图标成死链 | **已由 F10 解决**：监听 `SHCNE_RENAMEFOLDER` 自动改链接；通知丢失时降级为目录预判，再失败则标记失效 |
| **SHChangeNotify 通知延迟/丢失** | 链接没及时更新成新位置 | 降级路径兜底；条目右键菜单提供"重新定位"手动指定新路径 |
| **停靠带遮挡导致 drop 无效** | 在带上松手无反应（不会误判，仅无效） | 停靠带只占边缘一条；可选加 `WS_EX_TRANSPARENT` 彻底穿透 |
| **Shell 向 WinUI 迁移** | 窗口结构变化导致类名判定/热键取路径失效 | 类名 + 进程名双重判定；热键失效时降级为手动选择目录 |
| **拖拽起始检测漏判** | 接收区不出现 | Plan B 轮询 + 热键通道兜底 |
| **跨盘复制到自身子目录** | 可能递归 | 资源管理器会拒绝同盘移动；跨盘场景 P3 补一次路径预判 |
| **虚拟文件夹**（快速访问 / 此电脑 / 库） | 拿不到文件系统路径 | `IShellItem` 判断 `SFGAO_FILESYSTEM`，非文件系统直接拒绝并提示 |
| **高 DPI / 多显示器** | 位置错乱、图标模糊 | PerMonitorV2 + `GetDpiForWindow`；停靠位置按当前显示器工作区计算 |
| **老化节奏不合手感** | 图标消失太快或太慢 | 生命周期可配；支持一键关闭整个 F9 |

## 7. 分期计划与验收标准

**P1 — 骨架（0.5 天）**

- 托盘常驻、单实例、透明置顶窗口
- explorer 前台显示 / 切走隐藏

- 验收：同盘拖回是移动且**图标链接同步更新到新位置**；跨盘是复制；
  在资源管理器里手动移动文件夹，图标也跟随；按住 Ctrl 强制复制；拖到第三方应用可用

- 验收：重启后条目仍在；副屏位置正确

## 9. 发布方式

### 9.1 单文件发布是什么

.NET 应用默认发布出来是一个文件夹：一个 exe 加一堆 dll，且要求目标机器装了对应版本的 .NET 运行时。
**单文件发布**就是把运行时和所有依赖全部塞进这一个 exe，拿到手双击就跑，不用安装、不用管环境。

### 9.2 四种方案对比

| 方案 | 体积 | 目标机要求 | 说明 |
|---|---|---|---|
| 普通多文件 | ~5 MB | 需装 .NET 8 运行时 | 开发期用，发布快、便于调试 |
| 单文件 + 依赖运行时 | ~20 MB | 需装 .NET 8 运行时 | 体积小，但仍挑环境 |
| **单文件 + 自带运行时（选定）** | ~70 MB | **无要求** | 拷到任何 Win10/11 直接用 |
| 单文件 + 自带运行时 + 剪裁 | ~35 MB | 无要求 | WPF 大量反射绑定，剪裁有踩坑风险，不用 |

### 9.3 决定

- **开发期**：普通多文件发布，改完即测
- **交付版**：`self-contained` + `PublishSingleFile`，**不剪裁**，产出单个 exe 约 70 MB

理由：这是自用工具，70 MB 无所谓，但"拿到一个 exe 就能跑、换台电脑也不挑环境"很值钱。
WPF 不支持 Native AOT，也就不追求更极致的体积了。

命令：

```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

### 9.4 补充

- 开机自启走注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不写系统目录，不需要管理员
- 图标缓存、JSON 数据仍写在 `%LOCALAPPDATA%\DropBridge\`，与 exe 位置解耦
- 后续若要分发给同事，建议加个 `-p:IncludeNativeLibrariesForSelfExtract=true`，避免个别原生库解压失败

## 10. 构建环境

### 10.1 SDK 安装位置

需要 .NET 8 SDK（开发时用的是 8.0.424）。装在系统默认位置或用户目录都可以。

`build.bat` / `publish.bat` 会自动探测，不需要手工配路径：
先查 `PATH` 里的 `dotnet`，再依次找 `%ProgramFiles%\dotnet`、`%LOCALAPPDATA%\Microsoft\dotnet`。

### 10.2 必须补齐的环境变量（踩过的坑）

在某些受限 shell 中，`ProgramData` / `ProgramFiles` / `AppData` 等变量**未设置**（是 null，不是空字符串）。
NuGet 还原时会执行 `Path.Combine(ProgramFiles, "NuGet", "Config")` 去拼机器级配置目录，
拿到 null 会直接抛异常，且报错信息完全看不出原因：

```
NuGet.targets(745,5): error : Value cannot be null. (Parameter 'path1')
   at NuGet.Common.NuGetEnvironment.GetFolderPath(NuGetFolderPath folder)
   at NuGet.Configuration.XPlatMachineWideSetting..ctor()
```

排查手法：用 `dotnet fsi` 反射调用 `NuGetEnvironment.GetFolderPath`，逐个枚举 `NuGetFolderPath`，
看哪一项抛异常（实测 `MachineWideSettingsBaseDirectory` / `MachineWideConfigDirectory`）。

对策（已写进 `build.bat`，只在变量缺失时才补）：

```
if not defined ProgramData        set "ProgramData=C:\ProgramData"
if not defined ProgramFiles       set "ProgramFiles=C:\Program Files"
if not defined CommonProgramFiles set "CommonProgramFiles=C:\Program Files\Common Files"
if not defined APPDATA            set "APPDATA=%USERPROFILE%\AppData\Roaming"
```

### 10.3 WPF + WinForms 混用必须关隐式 using

`UseWPF` + `UseWindowsForms` 同时开启且 `ImplicitUsings=enable` 时，
SDK 会同时注入 `System.Drawing` 和 `System.Windows.Forms`，与 WPF 的类型大面积重名
（`Point` / `Image` / `MouseEventArgs` / `DragEventArgs` / `DragDropEffects` / `Color` …），
报 `CS0104 不明确的引用`。

对策：`<ImplicitUsings>disable</ImplicitUsings>`，逐文件显式 `using`。

### 10.4 高 DPI

manifest 里不要再写 `dpiAware` / `dpiAwareness`（会触发 `WFAC010` 警告），
改由项目属性 `<ApplicationHighDpiMode>PerMonitorV2</ApplicationHighDpiMode>` 配置。

## 11. v5 变更：左侧全高自由画布（2026-09-07 试用反馈后）

试用反馈提了两件事：① 双击悬浮图标打开文件夹发涩；② 想要"左侧从上到下全高、
宽度约屏宽 10%，图标像桌面一样自由摆放"。方案相应调整如下。

### 11.1 布局

| 项 | v4 | v5 |
|---|---|---|
| 停靠带 | 96px 窄条，垂直居中 | **左侧全高，宽 `clamp(屏宽 × 10%, 140, 260)`** |
| 图标排列 | 固定队列，自动排布 | **自由摆放，坐标持久化**（`BridgeItem.X / Y`，-1 表示未摆放） |
| 固定区 | 顶部独立分区 | **取消分区**，退化为"仅不老化"标记，位置照样自由 |
| 删除区 | 停靠带下末端 | **左下角 76×76**，仅拖拽期间浮出 |

新条目自动找空位（按列优先扫描，避开已有图标）。右键菜单提供"整理排列（全部重排）"。

### 11.2 鼠标穿透（关键约束）

全高 10% 的侧边条，宽度恰好约等于资源管理器左侧导航窗格（默认 ~200px）。
**若整条一直可点击，导航窗格就被完全挡死，这个宽度根本没法用。**

三态管理：

| 状态 | 判定 | 行为 |
|---|---|---|
| 平时 | — | 根容器 `Background="{x:Null}"` + `WM_NCHITTEST` 命中为空返回 `HTTRANSPARENT`，空白区穿透，仅图标可点 |
| 自身拖拽中 | `DoDragDrop` 期间 | 加 `WS_EX_TRANSPARENT` 整窗穿透，否则 topmost 的自己挡住下面的资源管理器 |
| 外部拖入 | 30ms 轮询 `GetAsyncKeyState(VK_LBUTTON)`，按下点落在 `CabinetWClass` | `Arm()`：铺 alpha=0x01 的画刷让整条参与命中测试，接住 drop；松手 `Disarm()` 还原 |

### 11.3 图标拖动：一次手势，三种落点

拖起图标即发起 `DoDragDrop(CF_HDROP + 自定义 ItemId)`，松手后按结果分流：

- `effect != None` → 被资源管理器或别的应用接收 → 视为使用，`LastUsedAt` 重置、`UseCount++`
- `effect == None` → 无人接收（窗口此时是穿透的），自己按光标坐标判定：
  - 落在删除区矩形 → 移除条目
  - 落在画布内 → 更新 `X / Y`（**不重置 `LastUsedAt`**：挪位置不算"使用"，否则拖一拖就永不老化）

### 11.4 老化：原位缓慢下沉

自由摆放后不能再用固定队列的"沿带下移"，改为按每个图标自身坐标动态计算：

```
travel  = max(0, 删除区上沿 − item.Y − ItemH)
offset  = progress × travel
opacity = 1 − 0.5 × progress
```

`progress = 1` 时图标正好落进删除区，随即移除并淡出。固定（Pinned）条目跳过计算。

### 11.5 打开文件夹不再发涩

`ShellWatcher.OpenInExplorer(path)`：先遍历 `Shell.Application.Windows()`，
找到已打开该路径的窗口就 `ShowWindowAsync(SW_RESTORE)` + `SetForegroundWindow` 激活（瞬时）；
没有才 `shell.Open(path)`；异常时兜底 `Process.Start("explorer.exe", path)`。
冷启动 explorer.exe 是几百毫秒到一秒多的开销，复用已开窗口可完全规避。
